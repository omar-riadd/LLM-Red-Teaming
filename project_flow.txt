LLM-REDTEAMER - PROJECT FLOW & BUILD LOG
High-Performance, Concurrent LLM Red-Teaming Framework (Rust)
=============================================================================

PROJECT OVERVIEW
================
"llm-redteamer" is a modular Rust workspace for automated red-teaming of
Large Language Models. It probes LLM backends with adversarial payloads,
detects vulnerabilities via pluggable detectors, and exports findings in
multiple report formats.

Architecture principles:
  - Strong type safety and zero-cost abstractions
  - Trait-based plugin system (object-safe, Arc<dyn Trait> dispatch)
  - Compile-time plugin registries via `inventory`
  - Concurrent execution via tokio (JoinSet, semaphores)
  - One unified error type across all crates

Workspace layout (6 crates):
  crates/redteamer-core           - types, errors, trait contracts
  crates/redteamer-adapters       - LLM backend adapters + factory
  crates/redteamer-payload        - payload mutation engine + YAML templates
  crates/redteamer-detectors      - string/regex/semantic/LLM-judge detectors
  crates/redteamer-probes         - OWASP-mapped attack probe library
  crates/redteamer-orchestrator   - scan campaign engine (ScanBuilder)
  crates/redteamer-reporters      - HTML / SARIF / Markdown / JSON exporters
  crates/redteamer-cli            - clap-based binary entry point
  templates/                      - YAML attack corpora embedded by probes
  docker-compose.yml              - local Ollama integration target

WEEK 1: Core crate scaffolding
------------------------------

What we built:

1. Workspace manifest: resolver = "2", shared dependency versions centralized
   in [workspace.dependencies], release profile with LTO + codegen-units=1.
   Member crates reference deps via `foo.workspace = true`.

2. error.rs - unified `RedTeamerError` enum using thiserror:
   - Adapter { adapter, message, source }   (named fields -> named format vars)
   - Probe(String), Detector(String), Report(String)  (tuple variants -> {0})
   - Unsupported(String), InvalidConfig(String)
   - Serialization(#[from] serde_json::Error)
   - Other(#[from] Box<dyn Error + Send + Sync>)   (escape hatch)
   - `Result<T, E = RedTeamerError>` alias used everywhere.

3. types.rs - core domain model:
   - OwaspCategory: enum for OWASP LLM Top 10 (PromptInjection .. 
     UnboundedConsumption) with const name(), id() ("LLM01".."LLM10"), and
     impact_score() baseline severities; Display impl "LLM01 (Prompt Injection)"
   - Verdict: Vulnerable | Resistant | Partial | Error (+ is_vulnerable())
   - OwaspMapping { category, relevance, rationale }
   - CvssVector { vector } with score() stubbed at 0.0 until Week 2 of Phase 1
     scoring engine; Severity enum with from_score bands
   - Finding { id, title, description, verdict, owasp_mappings, cvss,
               detector_name, probe_name, recorded_at, evidence_ids }
     with max_impact() = max(category.impact_score * relevance)
   - MutationType enum (None, CharacterSubstitution, WordSubstitution,
     EncodingWrapper, ContextFraming, ConversationalEscalation,
     TokenPerturbation, LanguageSwitch) + ALL const array
   - AttackRecord: full audit-trail entry per attempt (id, session_id,
     prompt, response, detections, verdict, timestamps, metadata)
   - DetectionOutcome { detector_name, matched, confidence, rationale }

4. traits/ - four object-safe async contracts (#[async_trait]):
   - TargetAdapter: info(), send(prompt), send_conversation() default ->
     Unsupported, health_check() default ping, enrich_record() no-op
   - Probe: name(), description(), category(), run(session_id, target,
     concurrency) -> Vec<AttackRecord>; per-attempt failures become
     Verdict::Error records, only fatal errors propagate
   - Detector: detect(prompt, Option<response>) -> DetectionOutcome
   - ReportExporter: format() + export(findings) -> count

Compile fixes applied during Week 1:
   a) thiserror format strings: tuple variants cannot use named vars like
      {probe} - changed to {0}
   b) Unsupported(&str literal) needed `.into()` to String
   c) with_rationale: `rationale.into()` required for impl Into<String>;
      removed `const` from fns calling non-const trait methods
   d) removed #[must_use] on associated const MutationType::ALL

WEEK 2: Five satellite crates
-----------------------------
Files created:
  crates/redteamer-adapters/{Cargo.toml, src/lib.rs, src/openai.rs}
  crates/redteamer-payload/{Cargo.toml, src/lib.rs, src/mutation.rs,
                            src/template.rs}

                              src/regex_set.rs}
  crates/redteamer-orchestrator/{Cargo.toml, src/lib.rs, src/scan.rs}
  crates/redteamer-cli/{Cargo.toml, src/main.rs}

1. redteamer-adapters:
   - RateLimiter: token-bucket (capacity + continuous refill_per_sec),
     async acquire() sleeping on deficit
   - OpenAiAdapter implementing TargetAdapter over reqwest: bearer auth,
     chat/completions wire types (subset), status/body error mapping into
     RedTeamerError::Adapter, usage stats into AdapterResponse::metadata,
     works with any OpenAI-compatible endpoint via with_base_url()

2. redteamer-payload:
   - Mutation enum (serde tag="type"): Identity, Base64, Rot13, Uppercase,
     Reverse, Wrap{prefix,suffix}; each with apply() -> String
   - MutationPipeline: ordered mutation set; iter(&self, seed) returns lazy
     impl Iterator borrowing both pipeline and seed (zero materialization);
     iter_with_identity guarantees raw seed first
   - ProbeTemplate: YAML-defined corpus (name, description,
     owasp_categories, seeds, mutations, detector_hints) matching serde
     renames; from_yaml/from_path with validation; payloads() matrix builder

3. redteamer-detectors:
   - StringMatchDetector: memchr memmem::Finder SIMD substring search,
     case-insensitive by default, needle leak via .leak() for 'static finders
   - RegexSetDetector: regex RegexSet single-pass multi-pattern evaluation;
     reports matched patterns as rationale

4. redteamer-orchestrator:
   - ScanConfig { session_id, target, probes, detectors, concurrency }
   - ScanBuilder: fluent registration, build() validates target present,
     DEFAULT_CONCURRENCY = 8
   - execute(): JoinSet fan-out per probe, aggregates records +
     failed_probes into ScanReport (with vulnerable_count())
   - spawn(): fire-and-forget tokio task returning JoinHandle<ScanReport>

5. redteamer-cli:
   - clap derive: `llm-redteamer scan --target --probes --format`
   - OutputFormat <-> core ReportFormat conversion
   - builds OpenAiAdapter from OPENAI_API_KEY env var

Compile fixes applied during Week 2:

   b) template.rs E0631: map_err(RedTeamerError::Other) -> closure boxing

1. inventory-based registry (src/lib.rs):

     callback, target.enrich_record() applied per result

   embeds templates/llm01_injection.yaml via include_str!; placeholder
   heuristic verdicts (compliance openers / instruction echo markers)

   first-person disclosure markers ("you are an ai", "system:")

   serde-typed JudgeVerdict {vulnerable, reasoning}, confidence mapping -

KEY DESIGN DECISIONS & LESSONS
=============================================================================

1. Unified error model: every fallible op funnels through RedTeamerError so
   plugins ?-propagate without per-crate plumbing. thiserror gotchas learned:
   tuple variants need positional {0} format args; struct variants can use
   named fields; #[from] Box<dyn Error + Send + Sync> works for escape hatch.

2. Object safety everywhere: all four plugin traits are object-safe and
   shared as Arc<dyn Trait>. Consequence: JoinSet tasks must be 'static ->
   owned data per task (cloned payloads, Arc'd evaluators), probes derive
   Clone, evaluators passed as Arc<dyn Fn>.

3. Resilience philosophy: per-attempt failures become Verdict::Error records
   (evidence, not crashes); detector panics degrade to negative outcomes;
   probe-level fatals collect into ScanReport::failed_probes. A campaign
   never dies because one request did.

4. const fn pitfalls hit twice: HashMap::new and trait-method calls are not
   const-callable; Vec::new is. Also #[must_use] on associated consts is
   deprecated.

5. Virtual workspace manifests cannot host tests/benches - targets belong to
   member crates.

6. Registry is link-time: probes register when their crate is linked; CLI
   must reference redteamer_probes (use ... as _;) or all_probes() returns
   empty.

7. Known stubs deferred to future phases:
   - CvssVector::score() (CVSS 4.0 math) - returns 0.0
   - SemanticDetector::embed() - ONNX inference wiring
   - LlmJudgeDetector::query_judge() - judge model transport
   - YAML AdapterConfig parsing (JSON only today)
   - CSV reporter
   - Session-id threading through ReportExporter signatures
   - MutationType precision in emitted AttackRecords

8. Verification loop used throughout: user compiles locally (no toolchain in
   the dev environment), pastes compiler errors back, fixes are applied
   incrementally - roughly 15 compile-error rounds across 5 phases.
